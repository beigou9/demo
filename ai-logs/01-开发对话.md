## 任务书要求

玩家替老周经营铁匠铺。核心循环是**接单 → 打造 → 交付 → 推进 → 结算**。打造操作要影响成品，交付反馈要影响下一轮。三天是任务书给出的设定，玩法、2D 或 3D、美术风格和具体结束条件由小组决定。
:codex-file-citation{path="实践课题：《老周的铁匠铺》学生任务书.docx" purpose="source"}

- **游戏**至少完整玩 3 轮，有 3 种不同订单或器型、1 个有操作手感的打造环节、新手提示和结算画面。
- **美术与声音**至少有 1 个场景、2 个角色形象、物品图标和基础 UI，风格统一。声音要有背景音乐和至少 3 种音效。
- **提交**包含源码和 `.git` 提交记录、可离线运行的 `release/`、1～2 分钟游戏录屏、`ai-logs/` 原始记录及 README。README 要写明组员分工、运行方式、素材许可和 4～6 个关键 AI 创作环节，说明人的取舍和修改。现场演示 5 分钟，至少讲一个人工改进 AI 产出的例子。
- **加分项**可以做 3D、角色动画、特效等制作技术，也可以接入运行时生成式 AI。两类都要在 README 附证据，运行时 AI 还要在超时或出错时回退，保证游戏能继续玩。

## 我对玩法的理解

画面上有不断到来的限时订单。玩家让几把刀在不同工作台上同时加工，每把刀按自己的工序推进，空台用来暂存半成品。简单刀工序少、分数低，复杂刀工序多、分数高。按时交付才得分，三关的目标分数逐步提高。

## 建议优先修改的地方

1. **给每关一个明确的结束规则。** 比如每关固定时长，到点按交付分数结算，达标进下一关，未达标可重试，第三关后展示三关总成绩。这样「订单倒计时」决定这单能否得分，「关卡倒计时」决定什么时候结算。
2. **只给铁砧加一个需要操作的判定。** 比如指针进入亮区时按下落锤，打准就提高交付得分，打偏仍能交付。其余工序按原设计计时。这样既保留多单调度，也能让玩家的打造操作直接影响结果。
3. **用三张示例订单把规则讲清楚。** 每张写出刀型、工序顺序、基础分和订单时限。再补一句半成品规则，例如「每个工作台和空台各只能放一把刀，工序结束后需要玩家搬走」。第一关的第一单可以用箭头带玩家走一遍，后面的订单再逐步要求并行处理。

我会保留「单工位、有限空台、多单并行」这三个现有设计。它们已经能让玩家做取舍，后续调难度时也有明确的地方可调。

## 实施规划

1. **先做一单可玩的原型。** 用色块摆出料架、炉台、铁砧、冷却槽和交付台。跑通小刀的「选单 → 搬运 → 加工 → 落锤 → 交付」。同时验证逾时会清掉刀坯并释放工位。
2. **再验证多单调度。** 加入第二张订单、两张暂存台和菜刀。用同一个铺面测一件具体的事：炉台和铁砧同时忙时，玩家能否一眼看清每把刀属于哪单、下一步该去哪，以及是否值得先腾工位。这个阶段优先调布局、交互距离和走路时间。
3. **把原型扩成三天。** 将刀型、工序、来单间隔和目标分数放进配置，订单、工位、计分与结算归到纯逻辑，场景负责输入和画面。接上柴刀解锁、练习单、失败重试和最终结算后，再用整局试玩调整 **100／170／260** 的目标分。
4. **最后接正式素材并验收。** 换上学徒图、工位美术和背景音乐，检查落锤、冷却、交付反馈。用 `npm run check` 验证规则，用 `npm run shot` 检查画面，再从封面手打到结算，最后用 `npm run pack` 生成并实测离线包。素材来源和 AI 创作取舍从第一轮就随开发记录。

素材制作的优先级是**背景音乐、俯视学徒、柴刀图标**。主场景先用现成设施搭起来，等多单并行确实好玩，再决定木台和走动动画要打磨到什么程度。
